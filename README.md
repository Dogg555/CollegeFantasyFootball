# College Fantasy Football

This repository contains a college fantasy football web app with a static frontend and a C++ Drogon API. The backend supports auth, league management, rosters, draft flow, waivers, trades, matchup scoring, CFBD-backed player ingestion, and Postgres persistence for hosted deployments.

## Directory layout
- `backend/` - Drogon API, CMake build, Dockerfile, and Postgres schema.
- `frontend/` - static HTML/CSS/JS app for leagues, players, draft room, waivers, trades, and settings.
- `render.yaml` - Render blueprint for the API and managed Postgres.

## Render deployment
Use `render.yaml` from the repo root to create the Docker web service and Postgres database.

Required environment:
- `DB_URL` - provided from the Render Postgres database connection string.
- `JWT_SECRET` - generated by Render or set manually.
- `ALLOWED_ORIGINS` - comma-separated frontend origins, for example `https://your-site.onrender.com`.
- `CFBD_API_KEY` - CollegeFootballData API key for player/stat ingestion.
- `CFF_REQUIRE_DB=true` - disables in-memory fallback behavior for production.
- `CFF_ALLOW_SHARED_SECRET_AUTH=false` - keeps the old shared-secret bearer-token shortcut disabled.
- `CFF_REQUIRE_EMAIL_VERIFICATION=false` - set `true` after an email provider is wired.
- `CFF_EXPOSE_AUTH_TOKENS=false` - keep reset/verification tokens out of HTTP responses outside test/dev.
- `CFF_LOG_AUTH_TOKENS=false` - keep reset/verification tokens out of server logs.

Frontend API configuration:
- Same-origin deploys use `/api` automatically.
- Separate static hosting can copy `frontend/config.sample.js` to `frontend/config.js` and set `window.CFF_API_BASE` to the Render API URL.
- `ALLOWED_ORIGINS` on the API must include the static frontend origin.

Deploy sequence:
1. Create the Render blueprint from this repo.
2. Confirm `ALLOWED_ORIGINS` and `CFBD_API_KEY` are set on the web service.
3. Render runs `sh /srv/db/migrate.sh` before deploy and records applied versions in `schema_migrations`.
4. Open `/health`; expected JSON includes `"status":"ok"` and `"database":"ok"`.
5. Sign up, create a league, then open `Players` and refresh the Data Ingestion panel.

Useful smoke checks after deploy:
- `GET /health`
- `POST /api/auth/signup`
- `POST /api/auth/login`
- `GET /api/leagues` with `Authorization: Bearer <token>`
- `GET /api/admin/ingest/cfbd/status` with `Authorization: Bearer <token>`
- `POST /api/admin/ingest/cfbd` with `Authorization: Bearer <token>` when `CFBD_API_KEY` is set.

Automated smoke test:
```sh
python scripts/api_smoke_tests.py
```

Set `CFF_API_BASE_URL=https://YOUR-RENDER-SERVICE.onrender.com` to run it against Render.

## What to keep out of git
- Environment files: `.env`, `.env.local`, and any machine-specific variants.
- Secrets and certificates: TLS keys, API keys, and anything under `certs/`.
- Local databases and cache artifacts: `db/`, Postgres dumps, Redis snapshots.
- Generated assets and OS cruft: build outputs, IDE settings, and temp files.

If sensitive material accidentally lands in the repo, remove it and rotate any exposed keys immediately.
